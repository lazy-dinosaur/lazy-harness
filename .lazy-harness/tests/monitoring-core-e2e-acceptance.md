## Source finding and change
Before this work the `RealtimeMaterialWindow` reset on every `input`, so the judge saw only the current turn; context-dependent checkpoints were structurally unanswerable. Added opt-in `historyTurns` (0..8, default 0 = unchanged behaviour): on an `input` frame, when the `conversation-history` kind is admitted, one material is derived from that frame's canonical projection (prior turns only, user/assistant/tool call/tool result lines, 800-char line clip, oldest lines dropped to fit maxSourceBytes), provenance = the input frame. It is replaced at each new input (no cross-intent reuse). Synthetic-only; real sessions need separate history-collection consent.

Side effect: `.lazy-harness/evidence/monitoring-core/realtime-B/identity.json` pins the old material.ts hash, so re-running the historical step3b pilot (`pilotIdentity`) would report baseline drift. Historical results are unchanged; a rerun would need a new identity.

## Evaluator
`.lazy-harness/scripts/monitoring-e2e-evaluate.ts`: per sequence one actual Pi1.4 SDK session; faux main provider replays gold assistant text and tool calls (custom `gold_tool` returns the gold tool results) so observation events are SDK-emitted; observer → material window (historyTurns 4) → realtime coordinator → selection bridge → injected judge → module packets. Per checkpoint it records decision, effective outcome (run only with a delivered packet; run without packet = run-undelivered), delivered knowledge reference IDs, history delivery and integrity issues (restricted body on wire, gold leak, grant violation). `score()` computes per-module recall, false-trigger rate, mode accuracy, defer recall, exact reference set rate and the tier verdict.
