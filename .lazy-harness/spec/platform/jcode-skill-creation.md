## Purpose

Allow lazy-harness to create project-local custom Jcode skills for a host while keeping the durable generator contract in `.lazy-harness`, not in `.jcode`.

This complements framework-owned wrapper skills generated by `jcode-wiring.ts`. Wrapper skills are fixed framework entrypoints. Custom skills are host-local workflow helpers generated on demand.

## Command contract

```bash
.lazy-harness/bin/lazy skill create <name> [options]
```

Options:

- `--description <text>` or `--description=<text>`: skill description.
- `--usage <text>` or `--usage=<text>`: command shown in the skill body.
- `--script <name>` or `--script=<name>`: also create `.jcode/skills/<name>/scripts/<script>`.
- `--allowed-tools <list>` or `--allowed-tools=<list>`: frontmatter `allowed-tools`; default `bash, read, grep`.
- `--force`: overwrite existing generated custom skill files.
- `--dry-run`: print planned writes without modifying files.

## Generated files

For a skill named `release-workflow`:

```text
.jcode/skills/release-workflow/SKILL.md
.jcode/skills/release-workflow/scripts/<script>   # optional
```

Generated skill files include the lazy-harness generated marker. Files without that marker are user-owned and must not be overwritten unless the user explicitly passes `--force` and the implementation still reports the overwrite.

## Metadata / audit output

Every applied creation or update appends one JSON object to:

```text
.lazy-harness/knowledge/skills.jsonl
```

Minimum fields:

- `id`
- `createdAt`
- `skillName`
- `skillPath`
- `scriptPath` when created
- `description`
- `allowedTools`
- `usage`
- `status`: `created` or `updated`
- `source`: `lazy skill create`

This file is host institutional memory. It is not Category A framework body and must not be overwritten by `lazy-sync`.

## Safety rules

- Skill names must match `^[a-z][a-z0-9-]{1,63}$`.
- Script names must match `^[a-zA-Z0-9._-]+$` and must not contain `/` or `..`.
- Do not overwrite user-owned `.jcode/skills/**/SKILL.md` by default.
- Keep custom skill logic local to the host unless promoted into framework scripts and manifests by explicit decision.
- When a custom skill encodes a team/project policy, record that policy in `.lazy-harness/{ssot,decisions,spec,behavior,tests,planning}/**`; the skill may point to the canonical record.
