Shared principles: (1) the current task/goal is explicit in state (LiteLLM sends the last user message as `task`; jev-compactor sends a `goal`); (2) code pins items that are never evaluated (system text, last user message, most recent exchange/turns, items mentioning goal file paths) and dedupes; (3) the unit is a whole exchange (tool call + its results, or an exchange plus its preceding exchange), kept or dropped together; (4) Jev sees the whole conversation (abridged skeleton) as read-only state, not a slice, so "superseded later" is judgeable; (5) asymmetric drop rule: drop only when confidently irrelevant (LiteLLM drops below keep-probability 0.2; jev-compactor drops at P(drop) >= 0.7); some use three fates keep / truncate / drop by confidence band; (6) budget-driven: nothing is sent to Jev below a token budget, and if still over budget the least-certain keeps go first (ranking, not a fixed gate); pi-fabric uses Jev salience only as a small ranking term next to TF-IDF, recency, role coverage and MMR under a byte budget. Differences in lazy-harness-monitoring compaction (`packages/core/src/engine/region-compaction.ts`): no explicit current request in state (fixed generic goal, event payload only sourceEvent), no pins, line-level items (tool call and result split), only the region is visible, a symmetric 0.5 keep gate, and it runs on every trigger regardless of size.
