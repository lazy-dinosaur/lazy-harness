corrected cleanup-first plan

Searchable Record Memory는 코드가 판단하는 시스템이 아니다

이 보고서는 이전 계획의 오염 지점을 제거하고, 새 PRD/tasks/plan이 어디를 어떻게 바꾸는지 설명합니다. 핵심은 LLM/searcher가 실제 record/source/test를 읽고 판단하고, 코드는 정적 debt/검증/cache만 담당한다는 점입니다.

왜 바꾸나 삭제 대상 새 흐름 세부 계획 검증 문서

1. 왜 이전 계획이 문제였나

문제

raw user text query

도구가 사용자 문장을 받아 후보를 반환하면, 결국 코드가 의미/중요도 판단처럼 보일 수 있습니다.

문제

helper architecture residue

삭제한 router/operational-state 흐름과 같은 종류의 오염이 남아 있었습니다.

문제

stale PRD/tasks

PRD와 task가 helper를 다시 살리는 방향으로 쓰여 있었습니다.

3. 새 동작 흐름

message.received
→ static harness-first search/read debt
→ LLM/searcher does root-bound grep/read/source/test inspection
→ LLM/searcher decides relevance, ambiguity gate, and next action
→ confirmed knowledge is written back to records
→ deterministic caches may be regenerated from records only
코드가 해도 됨
  • 정적 reminder 주입
  • sanitized debt row 기록
  • evidence가 있었는지 확인
  • 검증/측정/위생/캐시 생성
코드가 하면 안 됨
  • 사용자 의도 판단
  • 필수 read 선택
  • confidence/risk/gate/nextAction 산출
  • query helper를 lifecycle에서 실행

4. 새 세부 계획

  1. Decontamination: obsolete helper artifacts 삭제, runtime journal 개명, stale refs 제거.
  2. Static debt contract: search-read-debt-contract.md로 현재 남는 runtime path를 명확화.
  3. PRD/tasks/plan rewrite: LLM-owned retrieval 기준으로 전면 재작성.
  4. Deleted artifact protection: self-test에 파일/명령 부재 검증 추가.
  5. Record Index Header SDD/TDD: 구현 없이 record-authored metadata 표준만 먼저 작성.
  6. Cache/parser decision gate: context-index 이름 유지 여부부터 사용자 승인 후 구현.
  7. Record audit: 이후 advisory warning으로 검색 가능성 개선.
