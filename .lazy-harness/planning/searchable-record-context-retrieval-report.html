1. 한 줄 요약

목표: `.lazy-harness` record를 외부 기억처럼 검색 가능하게 만들되, CLI가 `requiredRead`, `confidence`, `intent`, `risk`, `nextAction` 같은 의미 결정을 하지 못하게 막습니다.

어디를 바꾸나

record 문서, context index, candidate retrieval CLI, record audit, graph query, self-test와 sync/doctor 검증 흐름을 바꿉니다.

어떻게 바꾸나

각 record에 ## Index header를 도입하고, CLI는 그 구조화 필드에서 후보 경로와 matched field만 반환하도록 정리합니다.

무엇이 좋아지나

LLM이 매 turn 전체 record를 뒤지는 대신 관련 후보를 빠르게 찾고, 실제 판단은 record/source/test read 근거로 수행하게 됩니다.

2. 현재 상태와 문제

현재 system reminder는 이미 모든 non-empty user message에 대해 정적 search/read debt를 주입합니다. 즉 "먼저 host root의 `.lazy-harness` record/source/test를 읽어라"는 안전장치는 있습니다. 하지만 그 다음 단계에서 LLM이 어떤 record를 먼저 볼지 찾는 검색 메타데이터가 아직 균일하지 않습니다.

문제의 핵심: record는 canonical truth지만, alias, surface term, source/test hint, graph id가 일정한 위치에 없어서 검색 품질이 낮고, full-file read가 늘어나며, CLI classifier를 다시 만들고 싶은 유혹이 생깁니다.

4. 변경 후 동작 흐름

이 계획은 system reminder 자체를 semantic하게 똑똑하게 만드는 계획이 아닙니다. reminder는 계속 정적 transport로 남고, 실제 개선은 그 다음 LLM/searcher가 사용할 후보 검색 표준과 도구에서 발생합니다.

1. User request
사용자 요청이 들어옵니다.
→
2. Static read/search debt
message.received가 동일한 harness-first reminder를 주입합니다.
3. Candidate tools
LLM/searcher가 Index header, graph, generated index, source grep을 사용해 후보를 찾습니다.
→
4. Real evidence read
선택한 record/source/test를 실제로 읽습니다.
5. LLM judgment
의도, 중요도, gate, next action은 LLM/searcher가 판단합니다.
→
6. Record capture
확인된 새 지식은 Index header + Implementation map + graph edge로 저장합니다.
user request
→ static message.received search/read debt
→ candidate retrieval from record-authored metadata
→ real record/source/test reads
→ LLM decides what matters
→ action or 3-5 option gate
→ confirmed knowledge stored back into .lazy-harness

6. 기대 개선 효과

현재 문제계획 후 개선검증 지표
LLM이 관련 record를 기억하지 못하거나 너무 많은 파일을 엽니다. Index header 기반 후보 검색으로 먼저 볼 record를 좁힙니다. candidate hits, fallback searches, prompt budget
host 별 alias나 product surface term이 record마다 흩어져 있습니다. Primary aliases, Surface terms, Search keys를 표준 필드로 모읍니다. records with index header 증가
source/test/graph 연결이 부족하면 구현 영향 범위 파악이 늦습니다. Implementation map + graph id + source/test hints를 검색 경로에 포함합니다. needs-map 31 감소
CLI classifier가 의미 판단을 대신하는 회귀 위험이 있습니다. schema와 self-test가 requiredRead, confidence, intent, risk, gate 출력을 금지합니다. self-test, forbidden-field grep/static checks
generated index가 canonical처럼 오해될 수 있습니다. generated cache는 non-canonical로 명시하고, record/graph/source read가 최종 근거가 됩니다. context-index delete fallback test

7. 절대 넘지 않는 금지선

No semantic authority

CLI는 raw user text로 intent, risk, importance, required read, next action을 결정하지 않습니다.

No generated truth

generated index는 cache일 뿐입니다. 충돌 시 record/graph/source가 우선입니다.

No full prompt dump

runtime prompt에는 compact instruction만 둡니다. full record dump는 하지 않습니다.

금지 출력 필드: requiredRead, optionalRead, confidence, instructionLevel, candidateMeanings, intent, risk, gate, nextAction
