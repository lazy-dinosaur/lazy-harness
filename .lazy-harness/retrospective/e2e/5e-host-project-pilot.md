## 4. Finding: test command routing must be project-owned

The pilot exposed a real framework gap:

- The affected runner had been calling `bun vitest run` directly.
- The host project's native command is `bun run test:run ...`.
- Therefore lazy-harness must never assume Vitest as the command surface.

Correct invariant:

```text
Project Init Interview / test-strategy
→ affected test command routing
→ package script fallback only when explicit project strategy is absent
→ structured interview if no safe command exists
```

## 5. Framework remediation

The affected runner is updated to prefer:

1. `.lazy-harness/tests/test-strategy.xml` or `--strategy` with an affected test command.
2. Repo-native package script fallback: `test:run`, then `test:unit`, then `test`.
3. Structured interview gate when no strategy/script exists.

It no longer hardcodes `bun vitest run`.
