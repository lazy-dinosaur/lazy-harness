## Rule/documentation model

Lazy-harness uses this split:

- `AGENTS.md` = grammar: stable framework-level instructions for when/how agents search, ask, and record.
- `.lazy-harness/{domain,spec,behavior,tests,decisions,ssot}/` = vocabulary: host-specific facts, contracts, decisions, scenarios, and source-of-truth records.
- `.jcode/` = private local harness wiring and personal workflow overlay for this checkout.

Project-specific rules should normally be records, not hardcoded into the shared grammar, unless they are generic enough to apply to every lazy-harness install.
