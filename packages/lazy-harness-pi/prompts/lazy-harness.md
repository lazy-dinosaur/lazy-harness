# Lazy-Harness Prompt

Use the host-local `.lazy-harness` records as the source of truth before host-specific claims or mutations.

1. At the start of a new host-dependent work unit, prefer one dedicated `lazy-harness.record-reader` subagent when it is executable. Launch it fresh/read-only with explicit `openai-codex/gpt-5.6-luna:low`, Agent Contract v1, `acceptance:false`, the active root as `cwd`, and no output/artifact. A separately approved task may override the child model, but no implicit global child default is allowed.
   Pass the Reader task as exact top-level `root:`, `revision:`, `model:`, `evidenceEpoch:`, `maxReadCalls:`, `maxRequestedLines:`, derived `maxLinesPerRead: floor(maxRequestedLines/maxReadCalls)`, and `task:` lines from the visible turn marker/current objective; the task model must equal the explicit launch model. Do not preselect record nodes. Omit `toolBudget` entirely: it counts overview/probes/drills as well as reads. Body budgets belong only in the task envelope.
2. While the Reader performs one complete map overview, concrete drill-down, and task-relevant canonical record reads, use the Parent lane for source/tests or immediately needed behavior. Discover existing source paths with native `find`/`grep` before any Parent body read; never guess a filename. Prefer native `read`/`grep`/`find` or a single simple read-only shell command; do not use redirection (including `2>/dev/null`), compound commands, or display pipelines. Prefer native tools. Implementation under `.lazy-harness/scripts/` is Parent source, not a canonical record directory. Parent remains the decision, mutation, integration, validation, and final-answer owner.
3. Before planning, mutation, or host-specific completion, wait for the content-bearing `LAZY_HARNESS_READER_RESULT: complete|incomplete|conflict` packet and explicitly close the join with `lazy_reader_join`, with status/result marker and exact revision/evidence epoch. Normally omit run ID, counters, and `recordPaths`: trusted runtime state supplies them, including `maxObservedReadLimit` and the failed-tool count. All successful ledger paths are revalidated and cached, even if a legacy caller supplies only a subset. Unread/duplicate supplied paths, identity mismatches, changed files and budget violations still fail. A process-complete acknowledgement alone is insufficient. Native async `subagent-notify` delivery is the completion path already consumed by the adapter. When no independent Parent work remains, yield control without a user-facing terminal answer so that notification can arrive; do not use status calls or shell commands merely to make time pass. Owned Reader status/transcript inspection is only a purposeful one-shot diagnostic and never content evidence or a join. If a lane fails while a child is pending, stop new work but drain its notification before emitting one final answer. A no-fallback canary reports failure after draining, without an incomplete join or another final response; normal work may use bounded fallback. `complete` avoids duplicate Parent record reads; any other state uses bounded direct fallback or an option gate.
4. If the dedicated Reader is unavailable or fails, run one `.lazy-harness/bin/lazy map --overview --complete --format=md`, drill one copied concrete node, and read the governing digest plus exact linked source/test directly.
5. Reuse unchanged joined/grounding evidence across later normal messages. Re-ground only for a new session, real scope change, explicit steer, changed/deleted governing record, or root/revision/epoch mismatch.
6. Never pass raw user text, long natural-language strings, or invented `--query` flags to `lazy map`; map/index output is navigation, not read proof.
7. Finish a coherent mutation batch before validation. Run `lazy check` once at a deliberate checkpoint, at most one focused/affected check per changed-behavior batch, and one final `lazy validate --plan standard`. Reserve direct `lazy test` for explicit fresh regression or commit/push/release gates.
8. Keep green validation output to status/count/time; store detailed logs outside the conversation. A post-response advisory must not replace the substantive Parent answer in non-interactive print mode.
